- **Types**: `types.ts` (Db, EventRow, Registration, Team, Profile, Notification, …). **Seed**: `seed.ts` (140 profiles; events incl. `knowledge-day-rag` 52/60 going, `alumni-night`, `c-battle-winter` draft missing English, `devhack-2027` application event with 64 applied + 16 teams, `members-meetup-live` happening now, `online-workshop-git` members-only; `PERSONAS`).

Add new pure selectors in your own file, not by editing `queries.ts`.
- **Write**: ONLY through the rules (each returns `Result<T>`; error codes `unauthenticated|forbidden|not_found|invalid|conflict|full|closed|rate_limited|server`): `registrations.ts` (`registerForEvent`, `cancelRegistration`, `decideRegistrations`, `sendDecisions`, `joinTeam`, `leaveTeam`), `members.ts` (`completeOnboarding`, `updatePrefs`, `applyForMembership`, `reviewMembership`, `setMemberStatus`, `mergeProfiles`, `grantRole`, `upsertSeason`), `events.ts` (`createEvent`, `updateEvent`, `previewEventChange`, `setEventStatus`, `EventInput`), `outbox.ts` (`retryNotification`, `dispatchOutbox`). Read the signatures and `tests/unit/mockdb-*.test.ts` to learn exact behavior. Do **not** edit these files; if you truly need a new rule, add `src/lib/mockdb/ext-<area>.ts` with its own unit tests and report it.
- **Server Actions**: `"use server"` files call `act((ctx) => rule(ctx, input))` from `src/lib/server/session.ts` (runs as the current persona, bumps the realtime version, expires cached public pages). Member-side actions already exist in `src/lib/me/actions.ts` (rsvp, cancelRsvp, applyToEvent, joinTeamByCode, leaveTeamAction, completeOnboardingAction, updatePrefsAction, applyForMembershipAction); reuse, do not duplicate. Server Actions return `Result` objects (never throw for expected failures); the UI maps each error code to a specific, helpful message.
- **Auth (mock)**: persona cookie. `getSession()`, `requireSession(lang, nextPath)`, `requireStaffPage(role?)` (404 for non-staff), `requireStaffAction(role?)`. Personas: `dev-admin` (admin), `dev-organizer` (organizer), `anuujin` (member), `temuulen` (guest), `saraa` (alumna), `new-guest` (not onboarded). Sign-in picker: `/[lang]/sign-in?next=…`.
- **Realtime**: the store notifies subscribers on every successful write; `<LiveRefresh/>` (`src/components/live/`) refreshes server-rendered pages live. Admin layout already includes it; `/me` and the public event page must include it too.
- Request-time reads (`cookies()`, `searchParams`, session) must sit **behind `<Suspense>`** (build error otherwise) with a skeleton that matches the final layout; `await connection()` before using `new Date()`/store data that must be fresh per request.

## 3. i18n: bilingual everywhere, with no edits to the shared dictionaries

